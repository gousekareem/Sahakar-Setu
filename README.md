# 01 · Overview

**SahakarSetu** began as a cooperative gig-services booking platform and has since evolved into a
full **Cooperative Workforce Operating System** — a digital layer that verifies worker skills,
intelligently matches workforce to demand, forecasts requirements, detects skill-capacity
shortages, enables **capacity sharing between cooperative societies**, and supports
**institutional bulk-workforce contracts**.

It is not simply "book a plumber." It is infrastructure for a cooperative-owned workforce
network connecting households, institutions, and Labour Cooperative Societies.

The platform creates a unified digital ecosystem for:

* Service discovery & booking
* Verified worker onboarding and a cooperative-issued **Skill Passport**
* AI-assisted workforce allocation
* AI-based demand forecasting and **shortage detection**
* Geo-spatial worker matching
* **Inter-cooperative capacity sharing**
* **Institutional bulk-workforce contracts & quotations**
* Transparent and fair wages, configurable per cooperative
* Digital payments, refunds and settlement runs
* Worker welfare, certification, and grievance/SOS handling
* Cooperative and platform-level administration & analytics
* Multilingual, accessible, offline-capable access

The core principle is simple:

> **Digitize the cooperative ecosystem without losing the cooperative at its centre.**

# 03 · The Problem

> **The problem is not a lack of service apps.**

Labour cooperatives already have skilled workers. Existing marketplaces already solve
one-off booking. The deeper problem is **fragmented workforce capacity**.

```text
Fragmented skilled labour
        +
Invisible cooperative capacity
        +
Trust gaps
        +
Demand-supply mismatch
        +
Limited inter-cooperative coordination
        =
UNDERUTILIZED WORKFORCE + INEFFICIENT SERVICE ACCESS
```

## Key Challenges

| Challenge                        | Impact                              |
| --------------------------------- | ------------------------------------ |
| Manual worker allocation          | Slower service matching              |
| Fragmented worker records         | Limited workforce visibility         |
| Informal service discovery        | Reduced customer trust               |
| Unclear wage distribution         | Limited transparency                 |
| Uneven workload                   | Inefficient worker utilization       |
| Limited demand intelligence       | Difficult workforce planning         |
| Fragmented welfare information    | Poor worker protection visibility    |
| Limited operational analytics     | Difficult decision-making            |
| Verification challenges           | Trust and quality concerns           |
| Isolated cooperative societies    | One society short-staffed while a nearby one has idle capacity |
| No institutional procurement      | Bulk workforce needs handled ad hoc, one worker at a time |
| No standardized skill identity    | Workers lack a portable, cooperative-backed credential |

### Result

```text
Fragmented Operations
        ↓
Manual Coordination
        ↓
Slow Matching
        ↓
Limited Transparency
        ↓
Disconnected Cooperatives
```

**SahakarSetu organizes the ecosystem.**

# 06 · Cooperative Hierarchy

SahakarSetu digitally represents the cooperative structure from federation to individual
workers — and now also connects **outward** to institutions procuring workforce.

```text
                    COOPERATIVE FEDERATION
                              |
              +---------------+---------------+
              |               |               |
              v               v               v
           SOCIETY A       SOCIETY B       SOCIETY C
              |               |               |
          +---+---+       +---+---+       +---+---+
          |   |   |       |   |   |       |   |   |
          v   v   v       v   v   v       v   v   v
         W1  W2  W3      W4  W5  W6      W7  W8  W9

              ^               ^               ^
              |               |               |
              +-------- CAPACITY SHARING ------+
                       (federated network)

        SOCIETY A  <---quote--->  INSTITUTIONAL CONTRACT
```

### Federation

Provides the broader cooperative governance structure.

### Society

Manages local workers, bookings, operations, welfare, live capacity, and its own fair-wage
configuration — and can now share workforce with, or borrow workforce from, other societies.

### Worker

Provides services through the cooperative and carries a portable, cooperative-verified
**Skill Passport**.

### Institution

Procures workforce in bulk directly from cooperative societies via structured contracts.

### Customer

Requests services from the verified cooperative workforce.

# 12 · AI Workforce Allocation Engine

## Intelligent Worker Matching

SahakarSetu does not simply select the nearest worker.

The system evaluates multiple factors to calculate a worker suitability score, and returns
**real worker coordinates** (not simulated positions).

```text
                         WORKER
                            |
       +--------------------+--------------------+
       |                    |                    |
       v                    v                    v
   Distance              Rating            Availability
       |                    |                    |
       +--------------------+--------------------+
                            |
              +-------------+-------------+
              |             |             |
              v             v             v
          Workload      Experience   Certification
              |             |             |
              +-------------+-------------+
                            |
                            v
                       MATCH SCORE
                            |
                            v
                  EXPLAINABLE RESULT
                            |
                            v
                   RECOMMENDED WORKER
```

### Matching Factors (weighted)

| Factor        | Weight | Purpose                             |
| ------------- | -----: | ------------------------------------ |
| Distance      |   30%  | Identify practical proximity         |
| Rating        |   20%  | Consider historical service quality  |
| Availability  |   15%  | Avoid unavailable workers             |
| Workload      |   15%  | Improve workload distribution         |
| Experience    |   10%  | Match relevant experience             |
| Certification |   10%  | Consider applicable credentials       |

### Explainable Recommendation

```text
+----------------------------------------+
|          AI WORKER RECOMMENDATION      |
+----------------------------------------+
|                                        |
| Worker: Recommended Electrician        |
|                                        |
| Distance:          1.8 km              |
| Rating:            4.8 / 5             |
| Availability:      Available           |
| Active Workload:   Low                 |
| Experience:        6 years             |
| Certification:    Relevant             |
|                                        |
| Match Score:       92%                 |
| Reason: nearby, certified, available,  |
|         4.8 rating, low workload       |
+----------------------------------------+
```

The objective is to make AI recommendations **understandable to cooperative administrators
and customers alike** — the ranking and the explanation are generated from the same numbers,
so they can never disagree.


# 47 · Honest Scope

SahakarSetu is a **hackathon-grade, judge-demonstrable prototype**, not yet a production
government platform.

The implementation prioritizes:

**Demonstrability · Explainability · Extensibility · Reliability**

| Area                 | Current Implementation                                |
| ---------------------- | -------------------------------------------------------- |
| Payments                 | Simulated `DemoProvider`, with refunds & settlements built on top |
| Identity                    | Cooperative-admin verification workflow                    |
| Notifications                 | In-app only; channel field ready for SMS/email/WhatsApp adapters |
| Maps                             | Leaflet + OpenStreetMap                                    |
| GPS                                | Real coordinates via manual/periodic worker push, not continuous background tracking |
| Mobile                                | Installable, offline-capable PWA (not a separate native app) |
| AI                                       | Lightweight, explainable models (linear trend + moving average; weighted multi-factor scoring) |
| Shortage figures                            | Bounded/capped, but skew slightly high due to intentionally dense seeded demand data |
| Database                                        | SQLite (Prisma's engine binaries weren't reachable in this build environment) |
| Two-way reviews                                    | API-complete (worker-rates-customer); frontend UI not yet built |
| Recurring bookings                                    | Schema fields present; auto-recreation logic & UI not yet built |
| Docker                                                   | Intentionally not included per project scope decision |
| Production Scale                                            | Requires PostgreSQL and infrastructure evolution (see §42) |

These limitations are intentionally documented rather than presented as production
integrations.

# 50 · Development Principles

SahakarSetu follows seven core principles.

```text
                    TRUST
                      |
                      v
                   FAIRNESS
                      |
                      v
                 INTELLIGENCE
                      |
                      v
                 COOPERATION
                      |
                      v
                CONNECTIVITY
                      |
                      v
                  INCLUSION
                      |
                      v
                    SCALE
```

### Trust

Verified workers, transparent operations, and an auditable admin trail.

### Fairness

Clear and configurable wage distribution, per cooperative society.

### Intelligence

AI-assisted workforce, demand, and shortage decisions.

### Cooperation

Technology built around cooperative institutions, not around replacing them.

### Connectivity

Cooperatives are connected to each other, not isolated — capacity sharing and institutional
contracts turn a single society's limits into a network's strength.

### Inclusion

Mobile-first, multilingual, offline-capable, and accessible access.

### Scale

Architecture designed for future expansion to state and national level.
